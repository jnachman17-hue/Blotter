# Legacy project archive

Files in this directory are historical working material.

They are not current project truth and must not override anything in `../docs/`.

They may contain:

- superseded strategy
- unvalidated product assumptions
- obsolete technical plans
- abandoned designs
- contradictory decisions
- AI-generated framing that Jon never firmly approved

Use these files only for context, idea recovery, design archaeology, or historical reasoning.

## Authority order

1. Jon's current explicit instruction
2. Confirmed decisions in `../docs/04-decision-log.md`
3. Current canonical documents in `../docs/`
4. Current `../docs/CURRENT-HANDOFF.md`
5. Files in this archive

Before reusing an archived idea, surface it as a historical proposal and re-evaluate it against the current validation-first strategy.

## Default reading rule

Do not read the full archive by default at the start of a new workflow. Read archived files only when a current task needs historical context, a canonical document points to them, or Jon explicitly asks for them.

Prior built pixels and design systems are scrapped. Archived design and implementation files are references and failure evidence only, not implementation targets.
